Rust 1.96.0 veröffentlicht

The Rust Release Team · 09.06.2026 · 1 Min Lesezeit

Rust 1.96.0 ist da

Das Rust-Team hat eine neue Version von Rust, 1.96.0, veröffentlicht. Rust ist eine Programmiersprache, die es ermöglicht, zuverlässige und effiziente Software zu erstellen.

Wenn du bereits eine vorherige Version von Rust über rustup installiert hast, kannst du 1.96.0 mit dem folgenden Befehl aktualisieren: $ rustup update stable. Wenn du rustup noch nicht hast, kannst du es von der entsprechenden Seite auf unserer Website herunterladen und die detaillierten Release-Notes für 1.96.0 lesen.

Wenn du uns helfen möchtest, zukünftige Versionen zu testen, kannst du lokal auf den Beta-Kanal (rustup default beta) oder den Nightly-Kanal (rustup default nightly) umstellen. Bitte melde uns alle Fehler, die du findest!

Was ist in 1.96.0 enthalten?

Neue Range*-Typen: Viele Benutzer erwarten, dass Range und verwandte core::ops-Typen Copy sind, aber das ist nicht der Fall. Sie implementieren Iterator direkt, und es ist ein Problem, sowohl Iterator als auch Copy auf demselben Typ zu implementieren.

  • core::range::Range
  • core::range::RangeFrom
  • core::range::RangeInclusive

Associated Iteratoren: Die neuen RangeInclusive-Typen machen ihre Felder öffentlich, im Gegensatz zu den Legacy-Typen, die den erschöpften Iterator-Zustand nicht offenlegen. Dies ist kein Problem mit den neuen Typen, da sie zum Beginn der Iteration umgewandelt werden müssen.

Bibliotheksautoren sollten die Verwendung von impl RangeBounds in öffentlichen APIs in Betracht ziehen, die sowohl Legacy- als auch neue Range-Typen akzeptieren. Wenn ein konkreter Typ benötigt wird, sollten die neuen Range-Typen bevorzugt werden, da sie eventually zum Standard werden.

Assert-Matching-Muster: Die neuen Makros assert_matches! und debug_assert_matches! überprüfen, ob ein Wert einem bestimmten Muster entspricht.

BytePost-Einordnung: Die neue Version von Rust bietet einige interessante Neuerungen, insbesondere die neuen Range*-Typen, die es ermöglichen, Slice-Accessor in Copy-Typen ohne Aufteilung von Start und Ende zu speichern. Dies kann zu einer verbesserten Lesbarkeit und Wartbarkeit von Code führen.
