OlmoEarth v1.1: Eine effizientere Familie von Erdbeobachtungsmodellen

Das Team hinter OlmoEarth hat inzwischen die Version 1.1 veröffentlicht. Seit der ersten Veröffentlichung im November 2025 haben Partner diese Modelle bereits für eine Vielzahl von Aufgaben eingesetzt, von der Überwachung von Mangrovenwäldern bis hin zur Klassifizierung von Treibern des Waldverlusts und der Erstellung von Karten über den Anbau von bestimmten Feldfrüchten auf Länderebene.

Bei der Verarbeitung von Satellitendaten durch OlmoEarth ist Effizienz entscheidend, um Prognosen über Tausende von Quadratkilometern hinweg zu ermöglichen. Die Kosten für die Berechnung sind dabei der größte Posten. Ein effizienteres Modell bedeutet, dass mehr Partner auf der OlmoEarth-Plattform unterstützt werden können und dass jeder, der OlmoEarth selbst ausführt, von dieser Technologie profitieren kann, ohne enorme Kosten zu verursachen.

Deshalb wurde OlmoEarth v1.1 entwickelt: eine neue Familie von Modellen, die die Rechenkosten um bis zu 3-mal senkt, während die Leistung von OlmoEarth v1 auf einer Mischung aus Forschungsbenchmarks und Aufgaben, die mit Partnern entwickelt wurden, beibehalten wird.

Effizienzsteigerung durch reduzierte Sequenzlängen

Die OlmoEarth-Modelle basieren auf Transformer-Architekturen, einer der dominanten Architekturen im Maschinellen Lernen heute. Um Remote-Sensing-Daten zu verarbeiten, werden diese zunächst in eine Sequenz von Token umgewandelt, die das Modell verarbeiten kann. Zwei wichtige Hebel kontrollieren die Effizienz in transformer-basierten Modellen: die Modellgröße und die Token-Sequenzlänge. Die Rechenkosten steigen quadratisch mit der Token-Sequenzlänge, sodass sogar kleine Reduktionen die Kosten für das Laufen des Modells erheblich senken können.

MACs (multiply-accumulate operations) schätzen die für einen Vorwärts-Pass durch das Modell benötigte Rechenleistung; geringere MACs bedeuten in der Regel billigere und schnellere Inferenz.

Token-Design

Das Entwerfen von Token wirft eine wichtige Frage für transformer-basierte Remote-Sensing-Modelle auf: Was sollte ein Token darstellen? Nehmen wir Sentinel-2-Bilder, ein häufig verarbeiteter Modus. Ein Sentinel-2-Eingabe-Token besteht aus einer Höhe und Breite (H, W, die die latitudinale und longitudinale Pixel darstellen), einer zeitlichen Dimension T und 12 Sentinel-2-Kanälen ([H, W, T, D=12]).

Bisher werden die Daten in auflösungsabhängige Patches unterteilt. Konkret bedeutet dies, dass ein bestimmtes räumliches Patches-Größe p gewählt wird und das gesamte Sentinel-2-Bild in Patches der Größe p x p unterteilt wird. Für jeden Patch wird ein Token pro Zeitpunkt pro Auflösung erstellt. So erhält ein Sentinel-2-Eingabe-Token mit 2 Zeitpunkten 6 Token pro Patch (2 Zeitpunkte x 3 Auflösungen, 10m, 20m und 60m). Insgesamt ergibt ein [H, W, T, D=12]-Sentinel-2-Eingabe-Token H/p x W/p x T x 3 Token.

BytePost-Einordnung: Die Entwicklung von OlmoEarth v1.1 ist ein wichtiger Schritt in Richtung effizienterer Erdbeobachtungsmodelle. Durch die Reduzierung der Rechenkosten kann das Modell von mehr Partnern genutzt werden und somit einen größeren Einfluss auf die Umweltüberwachung haben.
