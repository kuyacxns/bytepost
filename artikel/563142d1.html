Reachy Mini geht vollständig lokal

After building your Reachy Mini, installiere die Conversation-App und beginne, mit ihr zu sprechen. Bisher musstest du dein Audio an einen Server senden. Aber nicht mehr. Heute werden wir dir zeigen, wie du den gesamten Stack lokal ausführen kannst.

Dieser Stack wird von speech-to-speech angetrieben, unserer kaschierten VAD → STT → LLM → TTS-Pipeline, die eine Realtime-API-kompatible /v1/realtime-WebSocket-API bietet. Sobald du den Backend-Server startest, zeigt der Roboter darauf vom UI aus.

Kaskaden sind die flexibelste Option in der Open-Source-Landschaft heute und mit den richtigen Komponenten auch die schnellsten. Wir empfehlen die Komponenten, die wir am besten mögen, aber der Sinn einer Kaskade ist, dass du sie austauschen kannst. Neue Modelle werden jede Woche veröffentlicht.

Schnellstart

Dieser Blog führt dich durch die Ausführung von Gesprächen mit Reachy Mini vollständig lokal. Keine Cloud, keine API-Schlüssel, keine Daten verlassen dein Gerät. Hier ist ein Video, das es live zeigt:

Um die LLM auszuführen, verwenden wir Hugging Faces llama.cpp. Wenn du es installieren musst, ist der einfachste Weg, brew install llama.cpp oder winget install llama.cpp, für weitere Hilfe, sieh dir die Dokumentation an.

Als Erstes werden wir ausführen: llama-server -hf ggml-org/gemma-4-E4B-it-GGUF -np 2 -c 65536 -fa on --swa-full Und fertig! Beim ersten Mal wird das Modell heruntergeladen, bei nachfolgenden Starts ist es schnell.

Was bedeuten diese Flags? -hf ggml-org/gemma-4-E4B-it-GGUF — lädt das Modell direkt vom Hub. Der erste Start lädt es herunter, nachfolgende Starts verwenden den Cache. -np 2 — zwei parallele Slots. Lässt den Server einen zweiten Anfrage (z.B. eine schnelle Unterbrechung) ohne Blockierung des ersten bearbeiten. -c 65536 — 64k-Kontextfenster, geteilt über Slots. Viel Spielraum für lange Gespräche. -fa on — Flash-Aufmerksamkeit. Schneller und weniger Speicher, im Wesentlichen kostenlos auf moderner Hardware. --swa-full — behält den vollständigen Sliding-Window-Aufmerksamkeits-Cache anstelle von Neu berechnung. Tauscht ein bisschen RAM gegen bemerkbar schnelleres Prompt-Verarbeiten auf Gemma.

Einrichten von Sprache-zu-Sprache

Wir beginnen, indem wir einfach die Bibliothek uv installieren: pip install speech-to-speech

Während wir die LLM in einem anderen Terminal ausführen, können wir einfach ausführen: speech-to-speech --responses_api_base_url "http://127.0.0.1:8080" --responses_api_api_key "" --mode local Und du kannst beginnen, mit dem Modell über dein Terminal zu sprechen!

Das erste Mal benötigt es Parakeet-TDT 0.6B v3 und Qwen3TTS herunterzuladen, aber nachfolgende Starts sind schnell. Hier ist ein Video, das den lokalen Konversationsmodus zeigt:

Verbinden von Reachy Mini mit Sprache-zu-Sprache

Sobald du llama.cpp und speech-to-speech ausführen kannst, kannst du den Roboter mit der Desktop-App starten und die Conversation-App ausführen. Im UI der Conversation-App musst du den lokalen Modus durch Klicken auf "Verbindung bearbeiten" im HF-Backend auswählen.

Und du bist fertig. Du kannst beginnen, mit deinem Roboter zu sprechen. Jedes Stadium der Pipeline ist ein Kompromiss: Es gibt schnellere TTS-Modelle mit niedrigerer Qualität, langsamere STT-Modelle mit höherer Qualität. Wir haben für multilinguale Anwendungen optimiert, du möchtest möglicherweise für eine einzelne Sprache optimieren.

Der Rest des Blogs behandelt, wie du anpassen kannst.

Warum solltest du deinen eigenen Sprache-zu-Sprache-Server ausführen?

Hostierte Echtzeit-Backends sind bequem, aber das Ausführen deines eigenen Motors entsperrt drei Dinge: Privatsphäre. Audio verlässt dein Netzwerk nie, die gesamte Pipeline läuft auf Hardware, die du kontrollierst. Keine API-Kosten. Keine pro-Minute- oder pro-Token-Gebühren. Vollständige Kontrolle über die Pipeline. Tausche jede Komponente aus: VAD, STT, LLM, TTS. Wenn etwas Besseres im Hub 🤗 landet.

Das speech-to-speech-Repo gibt dir all das in einer einzelnen CLI. Es startet einen WebSocket-Server bei /v1/realtime, der das gleiche Protokoll spricht, das Reachy Mini bereits kennt.

Unsere voreingestellten Werte: VAD, STT, TTS Eine kaschierte Sprach-Pipeline hat vier Stadien: VAD, STT, LLM und TTS. Für drei davon wählen wir solide Vorgaben, damit du dich auf die LLM konzentrieren kannst:

  • Stufe: VAD, Wahl: Silero VAD v5, Warum: winzig, genau, läuft auf CPU. Das Standard-Default in der Open-Source-Stimme-Agent-Welt.
  • Stufe: STT, Wahl: Parakeet-TDT 0.6B v3, Warum: streaming-freundlich, sehr

BytePost-Einordnung: Die Fähigkeit, gesamte Pipelines lokal auszuführen, ist ein wichtiger Schritt in Richtung Privatsphäre und Kontrolle. Mit der richtigen Konfiguration kannst du ein leistungsfähiges und sicheres System aufbauen.
